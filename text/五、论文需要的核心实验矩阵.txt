Experiment B：packet sequence baselines

全部使用相同 packet feature、相同 split、相同 L：

Packet MLP + masked mean pooling；

LSTM；

GRU；

BiLSTM；

CNN1D；

Standard Transformer；

Ours BothEncoding。

当前 FlowLevelMLP 在没有 flow features 时已经支持对 packet token 做 masked mean，但比较脚本中相应模型被注释。建议增加：

self.models["PacketMeanMLP"] = FlowLevelMLP(
    input_dim=self.input_dim,
    hidden_dims=[256, 128, 64],
    dropout=0.3,
    num_classes=self.num_classes,
)

这很重要，因为它能回答：

提升来自 packet-level 原始特征，还是来自 Transformer sequence modeling？

Experiment D：序列长度

固定最佳模型和 head：

L = 16, 32, 64, 128

是否加入 256 应由 sequence length 分布和 GPU 成本决定。

报告：

完整 flow 覆盖率；

截断 flow 比例；

attack class F1；

Macro-F1；

PR-AUC；

显存；

inference latency。

不要只报告最大性能，还要解释性能与计算成本的折中。

Experiment G：flow fusion

固定最佳 packet model：

Packet only
Packet + flow gated fusion
Flow only

这三组能回答：

packet sequence 是否比 flow features 更好；

两种表示是否互补；

融合提升是否值得额外复杂度。
