JSON中的字段解析

在生成的 JSON 中，以下字段与 IPv4/IPv6 数据包的详细信息相关：

3.1 Header Length

IPv4：表示 IPv4 头的长度，通常是 20 字节，可能会因选项而增加。

IPv6：IPv6 头部长度固定为 40 字节。

3.2 Source IP 和 Destination IP

表示数据包的源 IP 地址和目标 IP 地址。根据数据包的类型（IPv4 或 IPv6）会自动填充相应的 IP 地址。

3.3 Protocol

指示数据包使用的协议类型，例如 6 表示 TCP，17 表示 UDP，1 表示 ICMP 等。

3.4 ToS (IPv4) 和 Traffic Class (IPv6)

在 JSON 中，它们被记录为数据包的服务类型或流量类别，用于表示数据包的优先级或服务质量。

3.5 Length 和 Payload Length

Length（IPv4）和 Payload Length（IPv6）表示数据包的有效载荷长度，告诉接收方有效数据的大小。

3.6 TTL 和 Hop Limit

分别表示 IPv4 的生存时间（TTL）和 IPv6 的跳数限制（Hop Limit）。

3.7 Checksum (IPv4)

记录 IPv4 数据包头的校验和，帮助验证数据包的完整性。

3.8 Source Port 和 Destination Port

如果数据包是 TCP 或 UDP 协议，则包括源端口和目标端口。

3.9 Payload

Payload 是数据包的有效负载内容。由于它通常是二进制数据，将其转换为十六进制字符串 是为了便于查看和存储。在 JSON 中，Payload 字段通常以十六进制格式存储，这样可以准确地记录原始数据包的内容。


为什么将 Payload 转换为 16 进制字符串

将数据包的负载部分（Payload）转换为 16 进制字符串 的原因如下：

4.1 可读性

原始的负载通常是二进制数据，直接存储或显示这些数据可能很难理解。将其转换为 16 进制字符串后，用户可以更容易地查看和分析其中的内容。

4.2 数据完整性

十六进制表示法保留了原始二进制数据的完整性。每个字节都可以精确地表示出来，因此能够忠实地记录传输的数据，而不会丢失任何信息。

4.3 存储和调试

对于后期存储和调试，16 进制字符串可以用来简化日志分析工具的处理过程，使得开发者或安全专家可以轻松地回溯到具体的网络攻击模式或恶意活动。

4.4 数据安全性

十六进制数据能够隐藏具体的内容，增加一些层次的安全性，尤其在日志存储或传输过程中，可以避免明文数据泄露。
